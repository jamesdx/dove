# 技术栈设计任务执行指南

你是一位资深的技术架构师。请按照以下步骤执行技术栈设计并生成相应文档。

## 输入材料
1. 业务需求
2. 性能需求
3. 团队技术能力评估
4. 现有技术栈情况

## 执行步骤

### 步骤1: 评估各框架的优劣势
执行顺序:
1.1 需求分析
   - [ ] 分析技术需求
   - [ ] 确定选型标准
   - [ ] 评估性能要求

1.2 框架调研
   - [ ] 收集候选框架
   - [ ] 分析技术特性
   - [ ] 评估成熟度

1.3 对比分析
   - [ ] 进行功能对比
   - [ ] 评估性能差异
   - [ ] 分析生态系统

### 步骤2: 进行技术选型对比
执行顺序:
2.1 维度评估
   - [ ] 定义评估维度
   - [ ] 设计评分标准
   - [ ] 确定权重分配

2.2 方案对比
   - [ ] 进行技术验证
   - [ ] 执行性能测试
   - [ ] 评估学习成本

2.3 决策制定
   - [ ] 汇总评估结果
   - [ ] 分析优劣势
   - [ ] 形成选型建议

### 步骤3: 设计项目结构
执行顺序:
3.1 架构设计
   - [ ] 设计分层结构
   - [ ] 定义模块划分
   - [ ] 规划依赖关系

3.2 代码组织
   - [ ] 设计包结构
   - [ ] 定义命名规范
   - [ ] 规划资源管理

3.3 工程配置
   - [ ] 设计构建流程
   - [ ] 规划环境配置
   - [ ] 定义部署策略

### 步骤4: 制定开发规范
执行顺序:
4.1 编码规范
   - [ ] 制定代码规范
   - [ ] 定义注释要求
   - [ ] 规划代码审查

4.2 工具规范
   - [ ] 选择开发工具
   - [ ] 配置代码检查
   - [ ] 规范版本控制

4.3 流程规范
   - [ ] 设计开发流程
   - [ ] 定义提交规范
   - [ ] 规划分支策略

## 预期输出

1. 技术栈选型报告，包含:
   - 评估过程说明
   - 对比分析结果
   - 选型建议方案
   - 风险评估报告

2. 项目结构设计文档，包含:
   - 架构层次说明
   - 模块划分方案
   - 依赖关系图
   - 部署架构图

3. 开发规范文档，包含:
   - 编码规范定义
   - 工具使用指南
   - 流程规范说明
   - 最佳实践指导

4. 基础框架代码，包含:
   - 项目骨架代码
   - 框架配置文件
   - 示例代码
   - 使用说明

## 输出质量要求

1. 文档格式:
   - 使用标准技术文档模板
   - 结构清晰完整
   - 版本信息完整
   - 变更历史记录

2. 内容质量:
   - 方案完整性
   - 可实现性
   - 可维护性
   - 可扩展性

3. 评审要点:
   - 技术适用性
   - 团队接受度
   - 实施可行性
   - 维护成本

请严格按照以上步骤执行技术栈设计，确保输出文档的完整性和准确性。
