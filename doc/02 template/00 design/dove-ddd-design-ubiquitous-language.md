## 2. 核心概念

### 2.1 订单领域
```markdown
1. 订单 (Order)
   定义：表示客户购买商品的交易记录
   属性：
   - 订单号：唯一标识
   - 订单状态：反映订单生命周期
   - 订单金额：订单的总价值
   业务规则：
   - 订单创建后不可修改订单号
   - 已支付订单不可取消
   使用场景：
   - 订单创建
   - 订单支付
   - 订单履行

2. 订单项 (Order Item)
   定义：订单中的具体商品条目
   属性：
   - 商品信息
   - 购买数量
   - 单价
   - 小计金额
   业务规则：
   - 数量必须大于0
   - 单价必须大于等于0
   关联概念：
   - 属于订单的组成部分
   - 关联具体商品
```

### 2.2 支付领域
```markdown
1. 支付单 (Payment)
   定义：订单支付的财务凭证
   属性：
   - 支付单号
   - 支付金额
   - 支付方式
   - 支付状态
   业务规则：
   - 支付金额必须与订单金额一致
   - 支付完成后状态不可变更
   使用场景：
   - 订单支付
   - 退款处理

2. 退款单 (Refund)
   定义：订单退款的财务凭证
   属性：
   - 退款单号
   - 退款金额
   - 退款原因
   - 退款状态
   业务规则：
   - 退款金额不能超过支付金额
   - 只能对已支付订单退款
```

## 3. 状态定义

### 3.1 订单状态
```markdown
1. 已创建 (CREATED)
   定义：订单初始状态
   触发条件：用户提交订单
   后续状态：待支付/已取消
   业务含义：订单已生成但未支付

2. 待支付 (PENDING_PAYMENT)
   定义：等待用户付款
   触发条件：订单创建成功
   后续状态：已支付/已取消
   业务含义：订单等待用户完成支付

3. 已支付 (PAID)
   定义：用户已完成付款
   触发条件：收到支付成功通知
   后续状态：已发货/已退款
   业务含义：订单已收到款项

4. 已发货 (SHIPPED)
   定义：商品已发出
   触发条件：仓库发货确认
   后续状态：已完成
   业务含义：订单商品已交付物流

5. 已完成 (COMPLETED)
   定义：订单完成状态
   触发条件：用户确认收货
   后续状态：无
   业务含义：订单全部流程完成

6. 已取消 (CANCELLED)
   定义：订单取消状态
   触发条件：用户取消/系统取消
   后续状态：无
   业务含义：订单交易终止
```

## 4. 关键行为

### 4.1 订单操作
```markdown
1. 创建订单 (Create Order)
   定义：生成新的订单记录
   前置条件：
   - 有效的购物车
   - 商品库存充足
   后置条件：
   - 生成订单记录
   - 锁定商品库存

2. 支付订单 (Pay Order)
   定义：完成订单付款
   前置条件：
   - 订单状态为待支付
   - 支付金额正确
   后置条件：
   - 更新订单状态
   - 生成支付记录
```

## 5. 跨上下文概念映射

### 5.1 订单-支付上下文
```markdown
1. 订单金额 vs 支付金额
   订单上下文：OrderAmount
   支付上下文：PaymentAmount
   映射规则：1:1 直接映射
   注意事项：精度和币种一致性

2. 订单状态 vs 支付状态
   订单上下文：OrderStatus.PAID
   支付上下文：PaymentStatus.SUCCESS
   映射规则：状态码转换
   注意事项：状态流转一致性
```
