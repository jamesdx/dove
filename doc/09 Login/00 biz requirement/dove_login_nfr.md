# 登录系统非功能性需求（NFR）信息文档

> 本文档汇总并细化登录系统在性能、可用性、安全合规、可维护性、可观测性、技术约束等非功能性方面的关键需求。

---

## 1. 性能需求

- **1.1 并发 & 吞吐量**  
  - 系统需支持日均 500 万 DAU，高峰并发 2 万 QPS
  - 登录认证处理能力需达到峰值 5000 TPS
  - 数据写入峰值支持每秒 10 万条日志处理

- **1.2 响应时间**  
  - 95% 登录请求需在 200ms 内完成响应
  - 99% 登录请求需在 500ms 内完成响应
  - 后端微服务间调用平均延迟需控制在 50ms 以内
  - 数据库查询响应时间不超过 100ms

- **1.3 峰值负载 & 扩展性**  
  - 系统需支持流量瞬时增长 5 倍的自动扩容能力
  - 单个登录服务实例支持 5000 QPS
  - 支持水平扩展，可根据负载自动扩缩容

- **1.4 其他性能关注点**  
  - 登录页面首屏加载时间控制在 1 秒以内
  - 验证码生成响应时间不超过 100ms
  - Token 验证耗时不超过 50ms

- **1.5 资源使用限制**
  - 单个服务实例内存使用不超过 2GB
  - CPU 使用率峰值不超过 75%
  - 每个容器最大连接数 5000
  - 数据库连接池大小根据实例配置自动调整

- **1.6 缓存策略**
  - 用户信息缓存命中率不低于 95%
  - 静态资源 CDN 缓存时间 7 天
  - 分布式缓存容量根据用户量自动扩展
  - 本地缓存大小限制 500MB

## 2. 可用性需求

- **2.1 SLA**  
  - 登录系统可用性 99.999%（每月允许中断时间不超过 26 秒）
  - 认证服务可用性 99.999%
  - 计划内维护时间不计入 SLA 统计

- **2.2 故障恢复目标**  
  - **RTO**: 故障恢复时间不超过 5 分钟
  - **RPO**: 数据丢失时间窗口不超过 1 分钟
  - 故障期间必须保证数据一致性

- **2.3 冗余 & 容灾策略**  
  - 采用多活架构，至少三个可用区部署
  - 用户认证信息多副本存储
  - 关键数据实时同步到灾备中心

- **2.4 关键运营时段**  
  - 7x24 小时不间断运行
  - 系统维护需在每周日凌晨 2:00-4:00 进行
  - 重大节假日实施重点保障机制

- **2.5 备份策略**
  - 用户数据每天全量备份一次
  - 关键操作日志实时同步备份
  - 备份数据保留 30 天
  - 备份恢复演练每季度进行一次

- **2.6 降级策略**
  - 定义三级降级方案
  - 超过 80% 负载启动一级降级（关闭非核心功能）
  - 超过 90% 负载启动二级降级（只保留基础登录功能）
  - 超过 95% 负载启动三级降级（开启登录排队）

- **2.7 限流策略**
  - IP 级别限流：每秒最多 100 次请求
  - 用户级别限流：每秒最多 10 次登录尝试
  - 接口级别限流：单个接口每秒最多 5000 次调用
  - 支持动态调整限流阈值

## 3. 安全与合规需求

- **3.1 数据隐私 / 合规标准**  
  - 严格遵守 GDPR、CCPA 等隐私保护法规
  - 实现用户数据访问追踪和导出功能
  - 敏感数据需进行脱敏处理

- **3.2 数据加密 / 传输安全**  
  - 所有登录通信必须使用 TLS 1.3
  - 密码传输采用非对称加密
  - 密码存储使用 bcrypt 加盐哈希（加密强度不低于12轮）
  - Session 信息采用 AES-256 加密

- **3.3 访问控制 / 鉴权**  
  - 实现基于 RBAC 的细粒度权限控制
  - 支持多因素认证（MFA）
  - JWT token 有效期限制为 30 分钟
  - 支持 IP 白名单和地理位置限制

- **3.4 日志审计 / 合规审计**  
  - 记录所有登录尝试的详细审计日志
  - 异常登录行为实时告警
  - 审计日志保留期限不少于 180 天

- **3.5 密码策略**
  - 密码最小长度 8 位
  - 必须包含大小写字母、数字和特殊字符
  - 密码有效期 90 天
  - 不允许使用前 5 次使用过的密码
  - 连续输错 5 次后锁定账号 30 分钟

- **3.6 会话管理**
  - Session 超时时间 30 分钟
  - 同一账号最多允许 3 个并发登录
  - 检测到异常登录时强制登出
  - 支持手动踢出其他登录设备

- **3.7 验证码机制**
  - 登录失败 3 次后启用图形验证码
  - 短信验证码 5 分钟内有效
  - 同一手机号每天最多发送 10 次验证码
  - 支持行为验证（滑块、点选等）

## 4. 可维护性、可观测性

- **4.1 代码质量 / 文档**  
  - 单元测试覆盖率不低于 85%
  - 代码必须通过 SonarQube 质量门禁
  - API 文档需使用 OpenAPI 3.0 规范

- **4.2 日志 & 监控**  
  - 使用 ELK 统一日志收集分析
  - 采用 Prometheus + Grafana 监控系统指标
  - 实现分布式链路追踪（Trace ID）
  - 记录详细的登录失败原因

- **4.3 告警策略**  
  - 登录失败率超过 5% 触发告警
  - 响应时间超过 500ms 触发告警
  - 连续失败登录次数超过阈值告警
  - CPU 使用率超过 80% 触发告警

- **4.4 问题定位**
  - P0 级别问题 15 分钟内定位原因
  - P1 级别问题 30 分钟内定位原因
  - 提供统一的问题定位平台
  - 支持全链路日志检索

- **4.5 监控指标**
  - 登录成功率
  - 验证码通过率
  - 各类登录方式使用占比
  - 登录来源 IP 分布
  - 登录设备类型分布
  - 异常登录事件统计

## 5. 技术选型偏好或限制

- **5.1 开发语言 & 框架**  
  - 后端：Spring Cloud Alibaba 和 Spring Cloud 技术栈 
  - 前端：Vue 3 + TypeScript
  - 数据库：MySQL 8.0

- **5.2 部署架构 & 环境**  
  - 容器化部署，使用 Kubernetes
  - 采用 GitLab CI/CD 自动化部署
  - 环境分为：开发、测试、预发、生产

- **5.3 中间件选型**  
  - 缓存：Redis Cluster（用于 Session 存储）
  - 消息队列：RocketMQ（用于异步日志）
  - 注册中心：Nacos

- **5.4 安全组件**
  - 验证码组件：极验行为验证 4.0
  - 加密组件：使用 Bouncy Castle 1.68
  - WAF：阿里云 WAF 企业版
  - 漏洞扫描：Fortify + SonarQube

- **5.5 监控工具链**
  - 日志：ELK 7.10.0
  - 监控：Prometheus 2.30.0 + Grafana 8.0
  - 链路追踪：SkyWalking 8.7.0
  - 告警：AlertManager + 自定义告警网关

## 6. 其他 NFR 需求

- **6.1 国际化 / 多语言**  
  - 登录界面支持中文、英文、日文
  - 错误提示信息多语言支持
  - 所有时间存储使用 UTC

- **6.2 兼容性要求**  
  - 支持主流浏览器最新两个版本
  - 移动端支持 iOS 14+ 和 Android 10+
  - 支持响应式布局

- **6.3 运维要求**
  - 运维人员需具备 K8s CKA 认证
  - 安全运维需具备 CISSP 认证
  - 提供 7x24 小时运维支持
  - 建立运维值班制度

- **6.4 文档要求**
  - 架构设计文档每季度审查更新
  - 运维操作手册实时更新
  - API 文档与代码实时同步
  - 问题处理手册定期复盘更新

- **6.5 第三方依赖服务**
  - 短信服务可用性 99.99%
  - 验证码服务响应时间 < 500ms
  - 所有第三方服务需提供备份方案
  - 核心第三方服务需双供应商

- **6.6 系统退出策略**
  - 提供数据导出接口
  - 用户数据留存遵守法律规定
  - 系统需支持平滑下线
  - 保留历史数据备份 180 天
